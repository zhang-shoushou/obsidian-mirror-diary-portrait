上面是一个可点击交互的原型，你可以点击左侧导航切换不同视图。下面我来系统地拆解这套 UI 的完整设计方案。

## 一、设计定位

产品气质：不是"数据分析工具"，而是"一面会说话的镜子"。

核心体验：温柔地揭示模式，邀请用户参与解读，而非输出冷冰冰的结论。

视觉隐喻：深夜书桌——暗色背景减少阅读压迫感，暖色点缀代表"被照亮的洞察"。

## 二、信息架构

```
镜像 · 日记画像系统
├── 第一层 · 自动分析
│   ├── 画像总览（Dashboard）← 默认入口
│   ├── 关系网络（Relationship Graph）
│   ├── 情绪时间线（Emotional Timeline）
│   └── 行为模式（Pattern Recognition）
├── 第二层 · 对话交互
│   ├── 与画像对话（Insight Chat）← 核心差异功能
│   └── 纠正记录（Correction Log）
└── 第三层 · 可视化看板
    ├── 自我规训看板（Self-Discipline Board）
    └── 里程碑（Milestones）
```

## 三、视觉设计系统

### 色彩

| 角色 | 色值 | 用途 |
|------|------|------|
| 背景主色 | #0f0f12 | 全局背景，降低长时间阅读疲劳 |
| 卡片背景 | #1a1a22 | 内容容器 |
| 层级背景 | #22222c | 输入框、标签、次级容器 |
| 边框 | #2a2a35 | 分割线、卡片边框 |
| 主文字 | #e8e8f0 | 标题、正文 |
| 次文字 | #9a9ab0 | 描述、元信息 |
| 弱化文字 | #6a6a80 | 时间戳、数据标签 |
| 暖橙（洞察） | #f5a623 | 主动提问、关键转折、里程碑 |
| 玫红（亲密/复杂） | #e85d75 | 关系网络中的复杂情感 |
| 天蓝（支持） | #5ac8fa | 温暖关系、已内化状态 |
| 薄荷绿（成长） | #34c759 | 积极趋势、坚持中 |
| 琥珀（警示） | #ff9500 | 反复出现但未执行 |
| 紫色（模式） | #af52de | 模式发现、系统推断 |

### 字体

- 主字体：系统无衬线字体栈（-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto）
- 标题：16-24px，字重 600
- 正文：13-14px，字重 400，行高 1.6-1.7
- 标签/元信息：10-12px，字重 400，大写或正常

### 布局

- 导航：左侧固定侧边栏（240px），顶部全局搜索栏（56px）
- 内容区：主内容区采用卡片式布局，间距 20px
- 响应式：侧边栏可收起为图标栏；看板类视图在窄屏下改为单列堆叠

## 四、各模块详细设计

### 1. 画像总览（Dashboard）

布局：2×2 卡片网格 + 顶部洞察横幅

核心组件：

**洞察横幅（Insight Banner）**

- 位置：页面顶部，全宽
- 样式：渐变暖橙背景（极低透明度）+ 左边框高亮
- 内容结构：[图标] + [模式描述 + 提问] + [操作按钮]
- 按钮："不对，不是这样"（纠正入口）、"展开聊聊"（进入对话）
- 设计意图：这是整个产品最核心的差异点——系统不输出结论，而是输出"模式+提问"。UI 上要用视觉权重强调它。

**情绪趋势卡片**

- 迷你折线图（Sparkline）：不显示坐标轴，只展示趋势
- 底部标签：显示当前主导情绪的变化方向（如"平静 ↑"），而非绝对状态
- 设计意图：避免"今天开心"这种单点判断，强调"趋势"

**关系焦点卡片**

- 列表形式：头像 + 名字 + 频率进度条 + 情感表情
- 进度条颜色对应情感类型
- 设计意图：快速扫描"谁在我的世界里占据了注意力"

**自我规训速览卡片**

- 三条代表性指令，用不同状态色区分
- 状态点：脉冲动画表示"反复出现但未执行"（引起注意）
- 设计意图：让用户一眼看到自己对自己的承诺执行情况

**行为模式卡片**

- 图标 + 标题 + 描述的三行结构
- 设计意图：模式描述要具体，带数据证据（如"日记字数增加 240%"）

### 2. 关系网络（Relationship Graph）

布局：左侧网络画布（占 2/3）+ 右侧人物详情面板（占 1/3）

**网络画布：**

- 力导向图或同心圆布局：用户在中心，他人按"心理距离"分布
- 视觉编码：
  - 颜色 = 情感温度（玫红=复杂，天蓝=温暖，琥珀=紧张，薄荷绿=疏远）
  - 大小 = 提及频率
  - 连线粗细/实虚 = 互动强度（实线=高频，虚线=低频）
- 悬停：节点放大 1.1 倍
- 点击：右侧面板加载该人物的详情

**人物详情面板：**

- 头部：大头像 + 名字 + 最近提及日期
- 时间线：该人物在日记中的出现记录（倒序）
- 洞察卡片：系统对该人物关系的模式推断
- 设计意图：点击一个人，看到的不是"统计数字"，而是"你们关系演变的叙事"

### 3. 情绪时间线（Emotional Timeline）

布局：垂直时间轴，单栏叙事流

**时间轴设计：**

- 左侧轴线 + 节点圆点
- 节点类型：
  - 普通事件：灰色小圆点
  - 里程碑（🏔）：暖橙色，较大
  - 关键转折（↺）：玫红色，带发光效果（box-shadow 脉冲）
- 卡片内容：
  - 日期标签
  - 事件标题（简洁，带情感关键词）
  - 描述（引用日记原文 + 系统解读）
  - 证据条（灰色小字，展示数据支撑）

设计意图：时间线不是"情绪打分"，而是"情绪变化的叙事"。关键转折点要 visually pop，让用户感受到"那一刻 something changed"。

### 4. 与画像对话（Insight Chat）

布局：类聊天界面，但带有"系统主动性"

**消息类型：**

- 系统消息：左侧，带 ◈ 头像，灰色气泡
- 用户消息：右侧，暖橙色气泡
- 主动提问消息：特殊样式——左边框高亮 + "主动提问"标签

**输入区：**

- 上方快捷提示（Hints）：展示可点击的示例问题
- 输入框：placeholder "问我关于你自己的任何事..."
- 设计意图：降低用户提问门槛，提示问题要覆盖三类：回顾类、对比类、模式验证类

**纠正机制：**

- 每条系统消息后附带"不对"按钮
- 点击后弹出轻量输入框："那是怎样的？"
- 纠正记录进入"纠正记录"页面

### 5. 自我规训看板（Self-Discipline Board）

布局：三列 Kanban 式看板

| 坚持中（薄荷绿） | 反复出现但未执行（琥珀色，脉冲） | 已内化（天蓝色） |
|------------------|----------------------------------|------------------|
| 卡片：指令标题 + 5 周柱状图 + 执行率 | 同左 + 底部洞察（系统追问） | 同左 + 底部证据（行为中自然体现） |

**柱状图设计：**

- 5 根柱子代表最近 5 个时间单位（周/月）
- 高度 = 执行率
- 颜色与列主题一致
- 设计意图：用微观趋势替代单点数据，让用户看到"坚持"是波动上升的

**状态定义的视觉表达：**

- 坚持中：静态绿色，给人稳定感
- 反复出现但未执行：脉冲动画，制造轻微焦虑感，促使用户关注
- 已内化：蓝色，平静，表示"这个问题已经解决了"

## 五、关键交互流程

### 流程 1：新日记触发分析 → 画像主动提问

```
1. 用户在 Obsidian/vault 中写入新日记
2. 系统检测到增量文件，自动解析 frontmatter（日期、标签）
3. 画像更新相关维度（关系频率、情绪词、自我指令等）
4. 若检测到"显著变化"（如某人频率骤降、新情绪词出现），生成主动提问
5. 提问以 Insight Banner 形式出现在 Dashboard 顶部，并带红点通知
6. 用户点击"展开聊聊" → 进入对话视图，上下文自动带入
```

### 流程 2：用户纠正画像推断

```
1. 用户在任意系统消息/洞察卡片中点击"不对，不是这样"
2. 界面展开轻量输入框（不跳转页面）
3. 用户输入纠正内容
4. 系统记录：原推断 + 用户纠正 + 时间戳
5. 该记录进入"纠正记录"页面
6. 后续同类推断权重降低，优先采用用户纠正后的模式
```

### 流程 3：从关系网络深挖日记片段

```
1. 用户在关系网络图中点击某个节点（如"代哥"）
2. 右侧面板滑入/更新，显示该人物详情
3. 时间线展示所有相关日记片段（带原文引用）
4. 用户点击某条记录 → 可选"查看原文"（打开对应日记）
5. 系统在该面板底部生成关系洞察，用户可一键带入对话追问
```

## 六、组件规范摘要

| 组件 | 规格 |
|------|------|
| 卡片 | bg-card + border + radius: 12px + padding: 20px |
| 按钮（主要） | bg-accent-warm + 黑字 + radius: 6px |
| 按钮（次要/纠正） | 透明 + 边框 + 悬停变玫红 |
| 标签/徽章 | bg-tertiary + 细边框 + radius: 12px |

| 头像 | 圆形，名字首字，颜色按关系类型分配 |
| 输入框 | bg-tertiary + 边框 + 聚焦时边框变暖橙 |

## 七、实现建议

前端框架：React/Vue + D3.js（关系网络）/ ECharts（情绪折线）

数据源：监听 Obsidian vault 文件变化（可用官方 API 或本地文件 watcher）

存储：本地优先（SQLite/IndexedDB），可选云端同步

文本分析：前端可用 compromise.js 做轻量 NLP，复杂分析可接本地模型或 API
